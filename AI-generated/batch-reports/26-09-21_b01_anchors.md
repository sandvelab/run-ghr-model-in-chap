# Batch 1 — Orient and pin the anchors

Generated from [[26-09-21_chapModelIntegrationRoutes]] — iteration 1

## What this batch was for

To fix, before anything is run, exactly what this project is running: which CHAP, which two
model repositories, which data. A comparison of two integration routes is only as meaningful
as the constancy of everything the routes share, and the way that constancy usually fails is
that nobody wrote down what "the platform" was until after the results existed.

## What was done

The repository was set up from `setup-guide.md`: `.venv` created, the invariant checker run
on the empty tree (all checks pass), the project defined in `readme-at-start.md` from the
plan, the root claim written, and the tree's four top-level nodes created — `01_anchors`,
`02_routeA_chapkit`, `03_routeB_mlproject`, `04_comparison`, as sub-analyses of the root.

The three anchors were pinned and archived with `provenance.md` and `README.md` beside each:

| Anchor | Pin | Where |
|---|---|---|
| Platform | `chap-core` 2.1.0, plus a 174-package freeze of the interpreter behind the `chap` entry point | `Archive/platform-chap/` |
| Route A model | `chap-models/chapkit_ghr_model` at `60b16a2`, GPL-3.0 | `Archive/model-route-a/` |
| Route B model | `dhis2-chap/minimalist_example_uv` at `5cd8a12`, no licence declared | `Archive/model-route-b/` |
| Data | `dhis2/climate-health-data` `lao/` at `af362d5`, three files with `sha256sums.txt` | `Archive/data-lao/` |

Both model clones had their `.git` directories removed after their commit was written to
`git-metadata.txt`, so that the archived trees are versioned by this repository rather than
sitting inside it as repositories this one cannot see.

`analysis/01_anchors/scripts/verify_anchors.py` re-verifies the data digests, reads the
schema, characterises the panel, and records every place the anchors' own documentation
disagrees with the artefacts. It writes three files and exits non-zero on a digest failure.

## What was established

All three data digests hold. The target is `disease_cases` — reported dengue cases — on an
18-unit, 156-month admin-1 panel from 1998-01 to 2010-12: 2808 rows, complete except for 233
rows with no target value; 1380 of the 2575 present values are zero, and the largest is 2643.

Four discrepancies were recorded rather than repaired, in
`analysis/01_anchors/results/anchor_discrepancies.tsv`:

1. The schema's `row_count` is 2575, which is the number of target-present rows, not the
   2808 rows the file has.
2. The schema names `LAO_ADM1.geojson`; the file present is
   `chap_LAO_admin1_monthly.geojson`, renamed upstream for CHAP compatibility.
3. 233 of 2808 rows have an empty `disease_cases` cell.
4. `minimalist_example_uv` declares no licence.

The first three are left as published on purpose: how each route copes with a schema that
does not match its data, and with a gappy target, is part of what this project is measuring,
and repairing them here would quietly remove the thing being observed.

## What this batch did not do

No model was run and no documentation for either model was read. Route A's and route B's
documentation is deliberately untouched by the orchestrating agent until each route's own
isolated agent has worked through it, because the orchestrator's prior exposure is exactly
what would make the discovery-effort comparison unmeasurable (plan §3).

## Open for the human

1. **Two anchors have no licence.** Neither `minimalist_example_uv` nor
   `dhis2/climate-health-data` declares one. This does not block the analysis; it blocks
   redistributing the archived copies at release. The decision is yours.
2. **`.claude/settings.json` still holds `<PARENT_DIR>` and `<HOME>` placeholders.** Two
   attempts to substitute them were refused by the session's permission classifier as
   self-modification. Until they are real paths, a parent directory's `CLAUDE.md` can reach
   this project's instructions, which `setup-guide.md` §2 exists to prevent.
3. **Docker.** The daemon was down when the anchors were pinned. Route A ships a
   `Dockerfile` and `compose.yml`, so batch 3 is likely to need it running.

count. Recorded in the plan's §4b.
